[[context:purpose]]
== Purpose

Repository:: `nbell0805/cadena-website`

This document provides medium- and high-level architectural context for future ChatGPT instances, coding agents, and contributors working on the Cadena Website repository.

The repository is primarily developed by Noah.

The intended contribution model for other contributors and agents is:

* understand the existing architecture and Sources of Truth before making changes;
* implement isolated proposals on dedicated branches;
* keep changes narrow and reviewable;
* submit Pull Requests rather than taking implicit ownership of unrelated frontend architecture;
* avoid remapping the complete repository for every new task.

This document is intentionally not a detailed Vue, JavaScript, or frontend-programming guide.

Its purpose is to establish:

* repository identity and canonical baseline;
* subsystem boundaries;
* Sources of Truth;
* runtime and service relationships;
* authentication boundaries;
* build and release conventions;
* environment behavior;
* deployment knowledge and unresolved areas;
* safe working conventions for future agents.

[[context:repository-sync]]
== Repository Synchronization Rule

Before beginning new work against `main`, synchronize the local reference explicitly.

Only use the hard-reset form when the local `main` is intended to be a clean mirror of `origin/main` and contains no local work that must be preserved.

[source,bash]
-----------------------------------------------------------------------------
git fetch --prune origin
git switch main
git reset --hard origin/main
-----------------------------------------------------------------------------

`git fetch --prune origin` removes stale local remote-tracking references for branches already deleted remotely.

It does not delete remote GitHub branches.

`git reset --hard origin/main` changes only the local `main` working state.

Remote branches are deleted only by an explicit remote deletion command, for example:

[source,bash]
-----------------------------------------------------------------------------
git push origin --delete <branch-name>
-----------------------------------------------------------------------------

Do not use an old local experimental branch as the basis for new work.

[[context:sot:http]]
=== Global Axios Behavior

Primary Source of Truth:: `src/api/axiosSetup.ts`

This is core infrastructure.

Responsibilities include:

* identifying whether an HTTP request targets the Cadena backend;
* attaching the Cadena JWT only to Cadena backend requests;
* avoiding accidental JWT disclosure to third-party services;
* observing successful Cadena backend responses;
* broadcasting authentication invalidation on `401` and `403`;
* signaling backend reachability or failure on network and server errors.

Do not casually modify this file.

[[context:branch-discipline]]
== Branch Discipline for Future Contributors and Agents

All proposals should be made on dedicated branches from the current target branch.

Typical branch naming:

[source,text]
-----------------------------------------------------------------------------
feature/<specific-change>
fix/<specific-bug>
docs/<specific-doc-change>
-----------------------------------------------------------------------------

Do not reuse an old generic test branch for production work.

Before branch creation, synchronize `main` when it contains no local work that must be preserved.

[source,bash]
-----------------------------------------------------------------------------
git fetch --prune origin
git switch main
git reset --hard origin/main
-----------------------------------------------------------------------------

Then create the working branch.

[source,bash]
-----------------------------------------------------------------------------
git switch -c feature/example-change
-----------------------------------------------------------------------------

Keep Pull Requests narrow.

Do not mix an intended functional change with opportunistic cleanup of:

* historical release ZIPs;
* unrelated Vue architecture;
* old comments;
* repository ownership metadata;
* environment-file policy;
* unused branches;
* unrelated SEO;
* unrelated formatting.

Such cleanup should be separately scoped if required.

[[context:remote-branches]]
== Remote Branch Safety

The repository contains numerous Noah-owned remote branches.

Normal fetch and synchronization operations do not delete them.

Commands such as:

[source,bash]
-----------------------------------------------------------------------------
git fetch --prune origin
-----------------------------------------------------------------------------

only clean stale local references to already-deleted remote branches.

Do not use:

[source,bash]
-----------------------------------------------------------------------------
git push origin --delete <branch-name>
-----------------------------------------------------------------------------

unless remote branch deletion is explicitly intended and authorized.

[[context:cautions]]
== Known Architectural Cautions

. Frontend TypeScript interfaces are useful but are not guaranteed to be the authoritative backend contract.

. Some frontend API handling supports historical response shapes.

. `src/config.ts` contains at least one stale development-proxy comment. Use `vite.config.mjs` for actual current proxy behavior.

. Cadena user authentication and Blog administrator authentication are separate systems.

. The repository combines transactional application functionality, marketing content, Blog/CMS, analytics, SEO and book-commerce functionality.

. Absence of route-level `requiresAuth` metadata does not prove that every operation on the route is anonymously available.

. Environment files are currently tracked despite `.gitignore` ignoring `.env*`.

. Environment values must be treated as potentially sensitive.

. Vercel configuration exists, but it does not establish the current complete deployment procedure.

. Local Netlify metadata exists but contains machine-specific configuration and is not a deployment Source of Truth.

. The release process deliberately commits release ZIP archives.

. Current `main` does not track `node_modules` or `dist`.

. Historical branches or releases may have different repository hygiene and should not be assumed to reflect current `main`.

. Package and repository metadata may contain stale historical ownership information. The actual Git remote and current branch history are more authoritative.
